## Exact storage and preservation

The importer calls the existing Accounts history repository. In glympse-patients, patient_id is the verified Cognito sub; username/revision/epoch are initialized only for a missing account. In glympse-meals, history#<snapshot>#<chunk> records contain gzip-compressed CSV bytes and record_type=history_chunk. The patient manifest points to the completed snapshot through history_id/history_chunks/revision/epoch. Publishing uses the repository's revision condition, preventing overwrite of a concurrent upload.

All source columns and cell strings are preserved in the CSV snapshot, including medications, missing cells, original Patient/Recording, additional columns, glucose precision and interpolation flags. CSV quoting/line endings may be canonicalized. validate_history checks compatibility without replacing the stored source values. The existing application normalizes Patient/Recording to current_user/active and exposes its supported columns on reads; extra original columns remain in durable storage. Naive source timestamps keep the same clock values; existing inference treats them as UTC, which is not a claim about the dataset's original timezone.

Historical meal descriptions appear through /history/readings and /live events, subject to the existing day-8 replay clock. They are NOT fabricated forecast# records: /meals returns confirmed predictions, not imported raw meal history. Creating forecast records would incorrectly introduce simulated meal effects. No predictions are generated by this importer.

An identical rerun is a no-op, with no duplicate chunks or meals. Different existing history is refused, not replaced/merged. Interrupted writes before manifest publication can leave inactive chunks under the existing repository design; no destructive cleanup is performed. Avoid simultaneous imports or uploads. Existing malformed patient manifests are not silently repaired.

## Operator IAM

The local operator needs cognito-idp:AdminGetUser on this user pool; DynamoDB GetItem/Query on the target tables for preview; and PutItem/UpdateItem for --write. This is an operator tool, not a Lambda endpoint; do not add Cognito administrator permission to the application role just for this script. It uses no passwords, tokens, hardcoded AWS keys, Scan or DeleteItem.
